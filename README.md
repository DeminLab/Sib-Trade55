# СИБ-ТРЕЙД

Сайт поставщика оборудования для благоустройства, металлоизделий и строительных товаров. СИБ-ТРЕЙД занимается подбором, продажей и поставкой продукции. Корзина оформляет **заявку на заказ без онлайн-оплаты**; стоимость и условия согласовываются с менеджером.

Документация дополнена по результатам реализации и локальных проверок 10 октября 2026 года. Подробная матрица — в docs/qa/REPORT-2026-10-10.md.

## Технологии

Next.js 16.4.0 (App Router), React 19.2.4, TypeScript, Tailwind CSS 4, shadcn/ui, Zustand, Zod и next-intl 4.14.9. Серверное хранилище — SQLite через `node:sqlite`; требуется **Node.js >= 22.13.0**. PostgreSQL используется для переноса прежних данных при инициализации SQLite и остаётся в Compose-конфигурациях. Android-приложение администратора находится в [`apps/admin-android`](apps/admin-android/README.md).

## Быстрый запуск в PowerShell

Команды выполняются из корня проекта. Если `.env` ещё отсутствует, создайте его из `.env.example`; существующий файл не перезаписывайте. Для локального запуска установите `NEXT_PUBLIC_BASE_URL=http://localhost:3000`.

```powershell
npm ci
npm run dev:next
```

Сайт доступен на [localhost:3000](http://localhost:3000). Сервер слушает `0.0.0.0`; для доступа с других устройств используйте текущий IPv4 компьютера. При смене сети проверьте `allowedDevOrigins` в `next.config.ts`.

`npm run dev` запускает **Docker Compose**, а не Next.js на хосте. Требуется запущенный Docker с Linux-контейнерами:

```powershell
npm run dev
# Остановка с сохранением томов:
npm run dev:docker:down
```

Хост и Docker development используют разные базы. Подробнее — [инструкция по запуску](docs/DEPLOYMENT.md).

## Возможности и границы

| Область | Текущее состояние |
| --- | --- |
| Каталог | Товары, категории, бренды, поиск, фильтры, сортировка и галерея; данные из SQLite |
| Корзина и избранное | Состояние браузера через Zustand/localStorage |
| Заказ | `/checkout` → `POST /api/orders` → SQLite; список заказов доступен администратору |
| Обращения, КП, ТЗ | SQLite, приватные вложения, статусы и повтор уведомления в админке |
| Telegram | Доставка после сохранения заявки; реальная доставка требует проверки с настройками бота |
| Управление каталогом | Редактирование товаров и категорий, изображения, архив и восстановление |
| Контент | Редактор страниц, блога, кейсов, материалов, покрытий и RAL; SQLite, архив/восстановление и защита от конфликтов |
| Авторизация | Серверный вход администратора; демонстрационные пользователи только вне production |
| Android для администратора | WebView для всех разделов админки и локальные уведомления о заказах, обращениях, КП и ТЗ; фоновая проверка не мгновенная |
| Посещения | `/admin/visitors`: анонимные браузеры, визиты и просмотры страниц, устройство, источник и время; IP и точная геолокация не сохраняются |
| Клиентский аккаунт | Регистрация демонстрационная; backend профиля, адресов и клиентской истории заказов не подключён |
| Интеграции | Типизированные адаптеры внешнего API присутствуют; CRM, оплата и внешний backend не подключены |

## Администратор

Для первого создания администратора задайте `ADMIN_EMAIL`, `ADMIN_PASSWORD` и `AUTH_SESSION_SECRET` в серверном окружении. При запуске приложения аккаунт создаётся в таблице SQLite `admin_accounts`; локально его можно создать командой `npm run admin:create`. Повторный запуск сохраняет существующий аккаунт и пароль. После создания `ADMIN_EMAIL` и `ADMIN_PASSWORD` можно убрать из окружения, но `AUTH_SESSION_SECRET` нужен для подписанных HttpOnly cookie. Вход: `/auth/login`, панель: `/admin`. Данные входа, хеши и файл базы не входят в Git. Подробности: [docs/admin-account.md](docs/admin-account.md).

В development доступен тестовый покупатель `demo@example.com` с паролем из `DEMO_AUTH_PASSWORD` (по умолчанию `password123`). Он отключён в production. Администратор во всех режимах входит через постоянный аккаунт в SQLite.

## Структура

```text
src/app/(store)/       Витрина, каталог, корзина, формы и аккаунт
src/app/(admin)/admin/ Панель администратора
src/app/api/           Route Handlers текущего backend
src/components/        Компоненты витрины, каталога и заявок
src/lib/database/      SQLite и перенос из PostgreSQL
src/lib/catalog/       Каталог, медиа, валидация и авторизация
src/lib/requests/      Заявки, вложения и уведомления
src/lib/orders/        Сохранение заказов
src/lib/repositories/  Доменные репозитории и внешние API-адаптеры
src/lib/services/      Клиентские и серверные сервисы
src/data/              Начальные JSON-данные
src/store/             Браузерное состояние Zustand
src/i18n/, messages/   Локаль и переводы
public/               Статические изображения и ресурсы
data/                 Локальная SQLite база и резервные копии (вне Git)
scripts/              Сборка standalone, импорт и обработка каталога
tests/                Тесты заявок и браузерный smoke-test
nginx/                HTTP reverse proxy
```

Основные маршруты: `/shop`, `/[slug]` (товар, категория или бренд), `/cart`, `/checkout`, `/quote`, `/custom`, `/contact`, `/cases`, `/materials`, `/blog`, `/pages/[slug]`. Админка: `/admin/visitors`, `/admin/products`, `/admin/categories`, `/admin/orders`, `/admin/contacts`, `/admin/quotes`, `/admin/custom-requests`, `/admin/content`, `/admin/portfolio`; раздел клиентов ожидает подключения customer API. Подробности сбора — [docs/visit-analytics.md](docs/visit-analytics.md).

## Проверки

```powershell
npm run lint
npx next typegen
npx tsc --noEmit
node --test tests/requests-store.test.mjs tests/sqlite-lock.test.mjs
npm run build
node tests/requests.integration.mjs
node tests/site.integration.mjs
```

`npm run build` собирает standalone и копирует статические ресурсы. `npm start` запускает `.next/standalone/server.js`; окружение и путь к базе задавайте по [инструкции](docs/DEPLOYMENT.md). Интеграционный тест использует отдельную временную базу. Команды выше — порядок проверки, а не заявление об их прохождении при каждом обновлении документации.

`tests/smoke-test.mjs` обновлён: берёт адреса категорий и товаров из текущей витрины, проверяет 320/768/1024/1440 px. Требует запущенный сервер и Edge; административные проверки включаются только с SMOKE_COOKIE. Фактические браузерные проверки этого запуска проводились через встроенный браузер, отдельно от скрипта.
